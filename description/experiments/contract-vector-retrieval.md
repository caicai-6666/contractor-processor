# 合同四向量内存召回实验

> **适用范围：** 本实验验证正式提取产物生成的合同名称、产品名称、摘要和 PDF 视觉向量，在小规模封闭候选集中的语义召回与变换鲁棒性。

## 用途与边界

实验调用正式 production 提取用例和正式 Embedding 客户端，但以进程内余弦相似度代替 Elasticsearch KNN。其目标是隔离观察向量本身的排序能力，避免索引参数、近似搜索和已有文档污染实验结论。

> **无入库副作用：** 实验不连接 Elasticsearch、不调用 `IngestReviewedContract`、不写入 `data/contracts`，也不保存高维向量或派生视觉 PDF。

自动提取结果保存在实验运行目录，仅作为候选向量输入和质量溯源证据，不构成专家终审，也不能进入正式合同库。

## 评估协议

每个输入合同同时作为一个候选目标。查询由版本化测试集预先指定，并采用唯一目标标注：

- 摘要：人工给定用户问题及一段不复制原摘要的假想合同文档，以后者模拟 HyDE 查询；
- 视觉：复用可复现 PDF 变换生成器，对多页合同删末页，对单页合同旋转和缩放；
- 合同名称：使用简写或局部业务关键词；
- 产品名称：使用俗称、简称、型号或原产品名称的一部分。

每条查询与同字段的全部候选向量计算余弦相似度，并记录完整降序排名。汇总指标为 Recall@1、Recall@3、MRR、目标平均相似度和目标相对最高错误候选的平均分差。

## 关键设计决策

候选文本严格遵循正式入库投影语义：合同名称来自 `contract_title`，产品名称优先使用 `normalized_name`、否则使用 `source_name`，摘要使用固定 Abstract 正文。文件名、独立型号字段和品牌字段不会额外拼入候选文本，因此型号查询失败时能够暴露正式投影的信息损失，而不是被实验特制文本掩盖。

HyDE 当前是固定人工假想文档，不额外调用生成模型。这样能够稳定复现和比较 Embedding 表现，但不衡量线上 HyDE 生成质量。视觉变换只覆盖当前变换器定义的删页、旋转和缩放，不代表扫描噪声、压缩、裁剪或页面重排的全部鲁棒性。

## 使用与依赖

运行入口、测试集格式及产物说明见[实验目录说明](../../experiments/contract_vector_retrieval/readme.md)。实验依赖 production MLLM、Qwen3-VL Embedding、PyMuPDF 和 `data/input` PDF，不依赖 Elasticsearch。

## 结果解释限制

封闭候选集规模较小时，Recall@K 容易偏高；合同名称又可能只描述文书类型，缺少主体或标的信息。正式应用前应扩充合同数量和困难负例，为一个查询允许标注多个相关合同，并分别比较精确 KNN 与目标索引的近似 KNN 表现。
