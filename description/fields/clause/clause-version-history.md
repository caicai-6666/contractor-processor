# Clause 条款提取版本记录

> **用途：** 本文保留 Clause 提取目录的历史设计演进。当前输出结构、切分规则与实现边界见 [Clause 条款提取目录](clause.md)。

---

## 0.5

- 合同级 Clause 产物增加程序生成的 SHA-256 `document_id`。
- 条款项仍严格保持原有五字段，不增加模型生成的 `clause_id`。

---

## 0.4

- 实验采用“结构穷举 → 全局边界整理 → 逐组资格筛选 → 单条抽取”的分阶段流程。
- 明确 `（n）标签：正文` 的标签属于子项自有标题，自有标题优先于父标题。
- 允许无自有标题的子项继承最近的原文明示父标题；相应原文不强制重复父标题。
- 允许程序由原文父编号和子项标记确定性组合层级引用，不使用浮点数或数组位置造号。
- Step 1B 只输出结构原子索引组，硬校验完整核销、连续、有序和非重叠，避免标题 / 正文重复与父子包含。
- Step 2 改为遍历“融合标题 + 来源原子 + 首尾硬边界”的只读投影，每次只生成 `reason + include/exclude`。
- Step 3 必须包含开始锚点且不得包含结束锚点；最终结果增加原文重复、包含及编号重复硬校验。
- 编号组合支持 `2.1` 和 `7.1`，避免再次生成 `七七、`、`71.` 等错误引用。
- 对锚点中的显式项目符号和标签执行可审计的程序归一化，并一次收集全部业务校验错误。

---

## 0.3

- Core 与 Clause 的 Step 1 拆分为独立模型任务，仅共享稳定的文本与 PDF 图像前缀。
- `heading` 改为非空硬门槛；原文没有明确标题时整个条目不得提取。
- 明确排除普通产品价格表、签署信息、银行账户和税务资料。
- 将 `quality`、`warranty`、`after_sales_service` 设为独立建议类别并强化相关内容召回。

---

## 0.2

- 确定 Clause 为有序条款列表和合同文本代理层。
- 确定 `clause_number/heading/category/source_text/page_refs` 五字段最小结构。
- 删除原规划中的 `clause_id`、`structured_summary`、`confidence` 和不确定原因。
- 明确数组顺序代替 `sequence`，内部唯一标识由程序生成。
- 增加独立两阶段 Clause 实验。
